## How to update this tracker

One checkpoint spans **four tables**, keyed by checkpoint ID. A 22-column single table is not legibly renderable, so the fields are split across Tables A–D; **every checkpoint has exactly one row in each**, and every required field appears exactly once. Update **all four** rows for a checkpoint in the same edit, at step 12 of the per-step implementation contract.

**Never mark a checkpoint `Accepted`.** Only the operator does that, and only after review.

### Status vocabulary

| Status | Meaning |
|---|---|
| `In progress` | Currently being worked |
| `Ready after F0 acceptance` | Unblocked once the operator accepts F0 |
| `Ready after relevant shared foundations` | Unblocked once F1/F2 (and F6 where rating-bearing) are accepted |
| `Blocked by …` | A named gate is not cleared |
| `Ready for review` | Work complete, agent stopped, awaiting operator review |
| `Accepted` | **Operator-set only** |
